# OV-Works 관리 콘솔 UI

첨부 UI/UX 예시의 서버 트리, 보조 메뉴, 상세 패널, 하단 이벤트 구조와
컨테이너 포털의 클러스터/네임스페이스 선택 방식을 참고해 구성했습니다.
예시 제품의 로고, 접근 토큰, 주소, 명령은 소스에 포함하지 않았습니다.

## 화면과 동작

- 로그인: 사용자 이름/비밀번호, 선택적인 사용자 이름 기억. 비밀번호와 세션 토큰은 localStorage에 저장하지 않습니다.
- 서버 보기: 데이터센터 → 클러스터 → 물리 호스트 → VM. 펼침 버튼과 대상 선택을 분리했습니다.
  트리 검색, 전체 VM 목록, 스토리지 목록, 패널 가로 크기 조절을 제공합니다.
- 상단 검색: 현재 성공적으로 조회한 Engine 인벤토리의 이름과 ID를 검색합니다. Kubernetes 전역 검색은 아닙니다.
- 요약: 실제 조회 건수, VM 실행 상태 분포, 호스트 상태, Engine 연결 확인.
  조회 실패 항목은 0개 대신 대시와 오류를 표시합니다.
- 자원 목록: 서버 페이지당 최대 50개, 현재 페이지 검색, 상세 선택.
- 상세: VM 요약, 디스크, NIC, 스냅샷, 콘솔 메타데이터. 호스트 상세에서 배치된 VM을 조회합니다.
- 하단: Engine 이벤트와 현재 브라우저 세션의 Engine 조회 기록을 별도 탭으로 제공합니다.
  서버 작업 이력 또는 영구 감사 로그를 대신하지 않습니다.
- 화면 설정: 목록 밀도, Engine 자동 갱신 간격(끔/30/60/120초), 하단 이벤트 표시 여부.
  설정은 현재 브라우저에 저장됩니다. Kubernetes 조회는 별도 수동 새로 고침입니다.
- Kubernetes: 공통 콘솔 안에서 클러스터·네임스페이스 선택, 자원 메뉴, 현재 페이지 검색,
  상세 속성 표, 선택적 JSON 보기, 컨테이너 로그, 노드→Pod 및 VM 연결을 제공합니다.
- 좁은 화면: 영역을 세로로 재배치하고 Kubernetes 메뉴는 관리 대상 선택 상자로 이용합니다.
- 설정/도움말 창은 native dialog를 사용해 키보드 포커스를 제한하고 Escape로 닫습니다.

## 기능 경계

예시의 VM/컨테이너 생성, migration, 콘솔 접속, 백업, RBAC 수정, 태그 편집 등은
현재 백엔드에 대응하는 기능이 없어 추가하지 않았습니다. VM 전원 작업은 계속 비활성화됩니다.
Engine CPU/메모리 시계열 그래프는 실제 데이터가 없으므로 임의로 생성하지 않고 미제공으로 표시합니다.
VM 메모리는 사용량이 아닌 설정 용량입니다. Kubernetes 메트릭은 기존 Metrics API를 그대로 사용합니다.

## 빌드와 브라우저 검증

```bash
cd frontend
npm install --include=dev
npm run build
# 최초 1회 브라우저 설치 (개발/CI 환경)
npx playwright install chromium
# 별도 터미널에서 README의 demo 백엔드와 npm run dev 실행 후
npm run test:ui
```

`test:ui`는 기본적으로 로컬 5173 포트에 접속하며 서버가 demo 모드인지 먼저 확인합니다.
기존 로그인 세션을 공유하지 않는 새 브라우저 컨텍스트에서 demo/demo를 사용합니다.
로그인/로그아웃, 검색, VM 디스크/NIC, 읽기 전용 작업, 설정 유지, 이벤트,
Kubernetes 로그/노드별 Pod/Secret 값 비노출/메트릭 미제공, 모바일 폭과
Engine 일부 조회 실패 시 상태 표시를 검증합니다.

선택 환경변수:
- `OMA_UI_TEST_URL`: 테스트할 데모 서버 주소
- `OMA_CHROMIUM_EXECUTABLE`: 설치된 Chromium 실행 파일 경로
- `OMA_UI_SCREENSHOTS`: 이미 존재하는 스크린샷 출력 디렉터리

실제 Engine 또는 Kubernetes 클러스터와의 인증·권한·데이터 호환성 검증은 별도입니다.
